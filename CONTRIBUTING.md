# Contributing to ConvertMe

Thanks for helping. ConvertMe is a local-first converter: a wheel under the pointer
picks a target, the engines crate does the work, and every job publishes a new file
next to its source. Fixes and additions are welcome on Linux; Windows packaging is
maintainer-owned because it needs native signing and hardware.

## Before you start

- **Bug in a conversion?** Open an issue with the input file's format, the exact
  command from Activity, and the tool versions from `convertme probe`. Do not attach
  files you cannot redistribute; a tiny synthetic sample is enough.
- **New format or tool?** Open an issue first. A new target has to earn its place in
  the planner and the UI contract, and that discussion is cheaper before the code.
- **Security problem?** Follow `SECURITY.md` instead of opening an issue.

## Getting it running

Rust 1.99 and Node 22 are pinned by `rust-toolchain.toml` and `ui/package.json`.
The build order matters: the GUI crate embeds `crates/convertme-gui/ui-dist` at
compile time and refuses to build when the bundle is older than `ui/src`.

```sh
npm --prefix ui ci
npm --prefix ui run build
cargo xtask gen-conf
cargo build --release -p convertme-gui --bin convertme
./target/release/convertme              # the window
./target/release/convertme probe        # which converters are installed
```

System libraries for the Tauri shell on Debian/Ubuntu:

```sh
sudo apt-get install libwebkit2gtk-4.1-dev libgtk-3-dev libsoup-3.0-dev \
  libxdo-dev libssl-dev pkg-config
```

Conversion itself shells out to whatever is installed. `convertme probe` lists the
gaps; install only the tools for the formats you care about.

## Before you push

```sh
./scripts/preflight.sh
```

That runs the identity gate, `cargo fmt --check`, `cargo clippy -D warnings`, the
workspace tests, the front-end build, and a clean-checkout build. A full
`./scripts/app-e2e.py` exercises the real window and takes about 16 minutes; run it
when you touch the wheel, a dialog, or drag handling.

CI additionally runs the front-end typecheck and geometry tests, the packaging job,
and the performance budgets. A budget regression is a failure, not a warning.

## Rules that are not negotiable

`AGENTS.md` is the short list and `docs/LESSONS.md` records the failures behind each
rule. The ones reviewers will ask about:

- **The source file is never modified.** Engines that mutate run on a staged copy.
- **Publish is atomic.** Work happens in a temp directory and is renamed into place;
  an existing file is never replaced.
- **No shell strings.** Every external tool gets an argv array. Filenames with
  spaces, quotes, newlines and emoji are normal input.
- **One edit, one representation.** A crop with a placed box sends `x/y/w/h` and no
  `aspect`; a second control owning the same value is a bug.
- **A tool dialog is one sheet.** The preview band is pinned outside the scroller, so
  inserting a line never moves the fields.
- **The UI/backend field contract is explicit.** A new control kind must be added to
  `ui/src/field-parse.ts` and covered by `npm --prefix ui run test:fields`.

## Commits and pull requests

Small, single-purpose commits with a subject in the imperative mood
(`tools: keep the page grid when the preview reloads`). Explain the measurement or
the failure that motivated the change in the body. Keep unrelated formatting out of
a functional commit.

A pull request should say what changed, what you ran, and what you could not verify.
"Not tested on Wayland" is a useful sentence; silence is not.

## Licence headers

New files do not need a per-file header. The project is GPL-3.0-or-later as a whole
(`LICENSE`), third-party components are listed in `NOTICE`, and the full Rust
dependency licence list is generated by `cargo about` for releases.
